# Ф5a. Методологическая сверка онтологии iono (2026-09-05)

Сверка [`../pyonto/`](../pyonto/README.md) с тремя работами по построению онтологий
(положены АХ в `lit/`): обзором методологий (Fernández-López & Gómez-Pérez), NeOn
(Gómez-Pérez & Suárez-Figueroa) и книгой Arp, Smith & Spear о BFO. Формат: конспект →
чем мы соответствуем → задокументированные отступления.

## 1. Fernández-López, Gómez-Pérez. Overview and analysis of methodologies for building ontologies (KER, 2002)

**Конспект.** Классический сравнительный обзор методологий: Uschold & King,
Grüninger & Fox (TOVE), METHONTOLOGY, On-To-Knowledge и др.; критерии сравнения —
наследование от IEEE 1074 (процессы управления/разработки/поддержки), степень зрелости,
зависимость от приложения. Ключевые общие элементы: спецификация через **компетентностные
вопросы** (Grüninger–Fox), жизненный цикл с итерациями, отделение концептуализации от
реализации, документирование каждого шага.

**Наше соответствие.** Онтология строилась по схеме Grüninger–Fox: мотивирующий сценарий
(интерпретация НЗ-ионограмм) → **56 компетентностных вопросов из [РД2023]** (см. Ф3
[03-angle.md](03-angle.md)) → формализация (OWL 2 RL) → проверочные аксиомы (SHACL-формы
как исполняемые компетентностные вопросы) → оценка (регрессия 18 сценариев). Жизненный
цикл итеративный: прототип → 5 ревью → цикл правок (журналировано в DIARY/README).

**Отступление.** Полного документа спецификации требований (ORSD) в формате METHONTOLOGY
нет — его роль играют Ф0–Ф3 + Э3; приемлемо для исследовательской онтологии, для
публикации стоит собрать ORSD-таблицу из Ф3.

## 2. Gómez-Pérez, Suárez-Figueroa. NeOn Methodology: a Scenario-based Methodology (2009)

**Конспект.** NeOn описывает 9 сценариев построения онтологических сетей; ключевые для нас:
Sc.1 (спецификация→реализация с нуля), Sc.2 (**реинжиниринг неонтологических ресурсов** —
тезаурусов, стандартов, БД), Sc.3 (переиспользование онтологических ресурсов), Sc.7
(реструктуризация). Акцент на сетевую модульность и повторное использование.

**Наше соответствие.** Проект — композиция сценариев NeOn:
- **Sc.2**: главный ресурс — нормативный документ [РД2023] (+[UAG23A]): перечни букв URSI,
  типов Es, причин ИОНКА реинжинирированы в модули quality/es/phenomena; SWRL-материалы
  Щирого (LLM-реинжиниринг того же РД) — вторичный ресурс, протокол сверки —
  [05-shiryi-merge.md](05-shiryi-merge.md).
- **Sc.3**: переиспользование BFO/IAO (минимальное, MIREOT-стиль — pyonto/README §BFO).
- **Sc.7**: реструктуризация 2026-09-03/04 (5 ревью → модули 0.2.0/ядро 0.3.0 → замкнутая
  директория с каталогом).
Модульность сети (core ← char ← quality ← phenomena; es; observation) — прямое следование
NeOn-архитектуре «онтологическая сеть», зафиксирована owl:imports.

## 3. Arp, Smith, Spear. Building Ontologies with Basic Formal Ontology (MIT Press, 2015)

**Конспект (принципы best practice, гл. 2–3 + категории BFO, гл. 4–7).** Реализм
(онтология описывает сущности мира, а не «концепты»); перспективизм и фаллибилизм;
низкая «стоимость входа» — выравнивание на верхний уровень BFO (continuant/occurrent);
принципы: **единственное утверждённое наследование**; униконность терминов (univocity);
аристотелевские определения «A =def. B, который C» (genus + differentia), без
циклов и отрицательных определений; каждый термин — с определением, источником и
метками; downward population из BFO-категорий.

**Наше соответствие (проверено программно, 2026-09-05):**
| принцип | статус у нас |
|---|---|
| выравнивание на BFO | 5 внешних классов задекларированы локально (BFO process/material entity/site, IAO ICE/measurement datum), все верхние классы iono — их подклассы |
| единственное утверждённое наследование | **0 нарушений** (скрипт-проверка: ни у одного класса нет 2+ именованных asserted-родителей; полииерархию даёт только ризонер через определяемые классы — как и предписывает книга) |
| реализм: сущности, не концепты | центральное различение «след (ICE) ≠ мода (процесс)»; классы-обозначения слоёв — задокументированное упрощение (М-03, отложено в 0.4) |
| определения с источником | аннотации переведены на ключи источников ([РД2023] §… с. N печ.); легенда — в заголовке каждого модуля |
| univocity | коллизия «RSF формат» vs «range-spread-F» выявлена ревью и задокументирована в phenomena |
| определяемые классы работают | автопроба: 21/21 применимых классов выводятся из признаков |

**Задокументированные отступления** (после доводки 2026-09-05 осталось два):
1. ~~Русские метки~~ — **ЗАКРЫТО**: все 253 сущности двуязычны (rdfs:label @ru + @en).
2. **Не полный импорт BFO** — MIREOT-минимум (обоснование: pyonto/README §BFO).
3. ~~Определения не аристотелевские~~ — **ЗАКРЫТО для ключевых классов**: 20 классов
   получили канонические определения «род + видовое отличие» через obo:IAO_0000115 @ru/@en;
   операционные комментарии сохранены отдельно (rdfs:comment). Остальные ~60 классов —
   постепенная доводка (0.4).
4. **Слои как индивиды-обозначения** (Layer_F2 и т.п.) — punning-упрощение вместо полной
   реификации LayerDesignation (М-03); оговорено в ядре. CamelCase-IRI сохранены
   (проектная конвенция; сами IRI — идентификаторы, семантику несут метки/определения).

## 4. Итог

Онтология методологически позиционируется так: **Grüninger–Fox** (компетентностные вопросы
из нормативного документа + исполняемая проверка) × **NeOn Sc.2+3+7** (реинжиниринг РД,
переиспользование BFO, реструктуризация по ревью) × **принципы Arp–Smith–Spear**
(выравнивание BFO, единственное наследование — проверено скриптом, определяемые классы —
проверены автопробой). Отступления перечислены и мотивированы — это и есть требуемая
книгой документированность решений.
