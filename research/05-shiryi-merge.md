## 2. Главные расхождения с нашей постановкой (почему не «взять как есть»)

1. **След ≠ мода.** В v1_2 моды — подклассы следа (`F2Mode ⊂ IonogramTrace`); у нас след —
   информационный объект, мода — процесс, связь `denotes` (ядро, тезисы §2). Это принципиально:
   на нём держится вся проверяемость интерпретации.
2. **Классы-индивиды.** `F2Layer`, `OrdinaryComponent` объявлены одновременно Class и
   NamedIndividual (punning без нужды); Es-типы — индивиды класса `ObservationEntity`.
3. **SWRL вне стека.** Наш профиль — OWL 2 RL + SHACL (тезисы: «числовые ограничения, невыразимые
   в DL, вынесены в SHACL»). Из 290 правил ~40 % тавтологичны («значение > 0 → InferredMeasurement»),
   ~30 % — классификация, выражаемая определяемыми классами, ~30 % — **настоящие инварианты РД с
   порогами** — их и переносим (в SHACL и в комментарии-эвристики).
4. **Три несовместимых namespace** и отсутствие аннотаций-источников.
5. Смешение предметного знания с техникой конкретной программы (стадии UI: `DateSelectedSession`,
   `DatabaseReadyRecord`) — не переносим.

## 4. Что сознательно НЕ перенесено

- сеансы-стадии обработки и записи БД (v1_2 R111–R130) — техника конкретного ПО;
- «unit factors» кода ИОНКА (RDSWRL R091–R104) — деталь сериализации телеграммы, место ей в
  кодере телеграмм, не в онтологии;
- спутниковое/риометрическое хозяйство (v1_2 R089–R110: гармоники гирочастоты, КСД, ППШ/АА/SID) —
  вне задачи интерпретации ионограмм ВЗ/НЗ; при необходимости — отдельным модулем;
- тавтологичные правила («X > 0 → измерение имеется») и дубли уже имеющегося в ядре
  (порядок высот слоёв = S4; кратности = hop count; O/X = MagnetoionicComponent).

## 5. Валидация (прогон 2026-09-03, rdflib 7.6 + owlrl + pyshacl)

- ядро + 5 модулей парсятся вместе: **1133 триплета, 87 классов**, коллизий имён нет;
- на сцене из реального SAO (MO155, 2019-001, день): ризонер выводит `Char_foE`, `Char_foF2`
  из кортежей признаков (метки нигде не задавались);
- Q-формы: перепутанные foE/foF2 → Q1 (Violation); fbEs > foEs → Q2; foEs ≤ foE без G → Q7
  (Warning); ошибка foF2 0,15 МГц без U → Q5 (Warning); та же сцена с проставленной G — conforms.

## 6. Вопросы, закрытые решениями (2026-09-03; на пересмотр соавтору)

1. **Буква G vs причина 7.** Решение: это два словаря одного смысла в разных носителях — буква
   сопровождает/заменяет число в таблицах и графиках, цифра кодирует отсутствие в телеграмме
   ИОНКА. Связь задана явно свойством `iono:correspondsToCause` (10 сопоставлений:
   A↔1, B↔2, C↔3, D↔4, E↔5, F/Q↔6, G↔7, R↔9, S↔0) в iono-quality.ttl, а не отождествлением.
2. **Недостающие типы Es.** Проверено по первоисточнику: скачан оригинал URSI Handbook UAG-23A
   (NOAA Institutional Repository, public domain), §4.83 (с. 4-21) распознан OCR: одиннадцать =
   девять стандартных **f, l, c, h, q, r, a, s, d** («flat, low, cusp, high, equatorial,
   retardation, auroral, slant, D region») + **k** (particle E) + **n** (не классифицируется).
   Типы d, k, n добавлены в iono-es.ttl с определениями из UAG-23A (d — не строго Es, ниже 95 км,
   не для fmin/foEs/h′Es; k — приоритет в табуляции; n — применять редко; = класс
   «неизвестно/аномалия» в ML-словаре).
3. **Z-компонента.** Решение: добавлена в перечисление ядра (`iono:zComponent`, версия ядра
   0.1.0 → 0.2.0) с аннотацией-обоснованием (буква Z, высокие широты, РД §6.5.4). Ядро — наш
   артефакт, правка согласована с его стилем; при возражениях первого автора легко откатывается.
4. **Пороги-реконструкции LLM** (spread-F 0,3 МГц / 30 км; наклоны/разрывы Es). Решение:
   оставлены как рабочие значения прототипа, но в аннотациях явно помечено «в РД отсутствует —
   реконструкция LLM, подлежит калибровке на размеченных данных». Числа из РД (0,05/0,15 МГц для
   foE; 0,1/0,2 МГц и 2/5 % для foF2; 0,3/0,4/0,5 МГц для разрыва Es; 0,5 МГц условия G) — со
   ссылками на параграфы и перенесены в SHACL-формы Q4–Q7.
