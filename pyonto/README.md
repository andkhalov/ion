# Онтология интерпретации ионограмм (iono) — v0.3.0-prototype

Модульная онтология семантической интерпретации ионограмм вертикального (ВЗ) и наклонного (НЗ)
зондирования. Стек: **OWL 2 (профиль RL) + SHACL**; проверка — `rdflib` + `owlrl` + `pyshacl`.
Для ML-конвейера онтология даёт две вещи: **словарь** (моды, характеристики, буквы качества,
типы Es, явления) и **исполняемую валидацию** физической допустимости разметки.
Чем она НЕ является: не детектор следов, не парсер SAO/RSF, не модель ионосферы.

Прошла пять независимых ревью (методология BFO/OWL, радиофизика, SHACL-техника, сверка с
источниками, «читатель со стороны») и цикл правок; полные отчёты ревью удалены при
рефакторинге проекта 2026-09-04 — применённые исправления зафиксированы в этом README и в
аннотациях модулей. Регрессионный набор: `python -m pyon.validate` из корня проекта →
«ВСЕ ТЕСТЫ PASS» (18 сценариев).

**Структура директории (замкнутая):** точка входа словаря — **`iono-all.ttl`**
(owl:imports шести модулей); формы `iono-shapes*.ttl` подаются в pyshacl отдельным графом;
`ground-A/B/C.ttl` — эталонные сцены регрессии. Код проверки — `pyon/validate.py` (вне этой
директории: онтология — данные, код — библиотека).

**Protégé.** IRI `http://scilibai.ru/onto/...` в вебе не разрешаются — импорты маппируются
на локальные файлы через **`catalog-v001.xml`** (OASIS XML Catalog, лежит рядом): открывайте
`iono-all.ttl`, Protégé подхватит каталог из той же папки автоматически и подтянет все шесть
модулей. Замкнутость проверена: каждый owl:imports каждого файла разрешается каталогом,
внешних импортов нет. ВНИМАНИЕ: в каталоге АБСОЛЮТНЫЕ file://-пути — при переносе на другую
машину перегенерировать (пути поменять на новые; сам список из 12 IRI неизменен).

**Происхождение.** Онтология включает переработанные материалы соавтора А. О. Щирого
(LLM-генерация по РД 52.26.817–2023: ~290 SWRL-правил, перечни букв URSI, типов Es, причин
ИОНКА) — они послужили затравкой модулей char/quality/es/phenomena; исходные файлы удалены
при рефакторинге, протокол сверки и решений — `research/05-shiryi-merge.md`.

**Переиспользование BFO 2020 / IAO (OBO Foundry) — что именно и зачем.** Полного импорта
BFO НЕТ и он не нужен: используется стандартная практика минимального заимствования
(в духе MIREOT — Minimum Information to Reference an External Ontology Term): четыре внешних
класса задекларированы ЛОКАЛЬНО в `iono-core.ttl` (блок 0) с их каноническими IRI, метками и
комментариями: `obo:BFO_0000015` process — процессы распространения и сеансы;
`obo:BFO_0000040` material entity — ионозонд, пункт, трасса; `obo:BFO_0000029` site — слои;
`obo:IAO_0000030` information content entity — ионограмма, след, данные, урсиграммы.
Что это даёт: (а) методологическую заявку «онтология выровнена на BFO 2020» с проверяемыми
IRI (важно для рецензентов онтологической части); (б) корректную организацию верхнего уровня
в Protégé (классы видны, т.к. задекларированы локально — ничего скачивать не нужно);
(в) будущую интероперабельность. Чего НЕ даёт и почему это ок: аксиомы самого BFO
(дизъюнктности категорий и пр.) в замыкании не участвуют — наши проверки на них не
опираются (свои AllDisjointClasses заданы в ядре), а полный импорт (~сотни аксиом,
конструкции вне RL-профиля) замедлил бы owlrl/pyshacl без функциональной пользы.
Если когда-нибудь понадобится строгая DL-проверка соответствия BFO — подключить
bfo-core.owl отдельным профилем, не в рабочем конвейере.

**Выводимость проверена автоматически**: для каждого определяемого класса построен
пробный индивид из признаков его пересечения → owlrl-замыкание — **21/21 применимых классов

**Двуязычие (закрыто 2026-09-05).** Все 253 сущности имеют rdfs:label @ru И @en

остаются в rdfs:comment.

**Принцип единственного утверждённого родителя** ([ArpSmithSpear2015], гл. «best practices»):
0 нарушений (ни один класс не имеет двух именованных asserted-родителей).

## 1. Ключевое различение: след ≠ мода

**След (`iono:IonogramTrace`)** — информационный объект (IAO ICE): яркая кривая на ионограмме.
**Мода (`iono:PropagationMode`)** — реальный процесс распространения радиоволны (BFO occurrent).
Интерпретация = отношение **`iono:denotes`** «след обозначает моду». Всё остальное — вокруг этого:
характеристики (`iono:CharacteristicDatum`) — данные измерения, снятые с ионограммы; буквы URSI —
оценка их качества; формы SHACL — проверка, что набор утверждений физически возможен.

**Мода и характеристика — не метки, а кортежи признаков.** Мода: кратность × слой × тип луча ×
компонента; характеристика: вид величины × слой × компонента. Имя класса (`Mode_1F2`, `Char_foF2`)
**выводит ризонер** из признаков; писать в данных нужно признаки:

```turtle
ex:m1 a iono:PropagationMode ;
    iono:hasHopCount 1 ;                          # xsd:integer!
    iono:hasRayType iono:lowerRay ;
    iono:hasMagnetoionicComponent iono:ordinary ;
    iono:reflectsFromLayer iono:Layer_F2 .        # или через hasTrajectorySegment/reflectsFrom
# ризонер выведет: ex:m1 a iono:Mode_1F2
```

⚠ Обратное направление в OWL 2 RL **не работает**: `ex:m1 a iono:Mode_1F2` без признаков не даёт
`reflectsFromLayer`, и мода выпадает из всех проверок (страхует форма H5, Warning).

## 3. Как запустить проверку (единственный правильный порядок)

```python
from validate import load_vocabulary, validate_scene, dec
from rdflib import Graph
scene = Graph(); scene.parse("моя_сцена.ttl")
r = validate_scene(scene)          # или: python -m pyon.validate моя_сцена.ttl
# r = {hygiene_ok, violations, warnings}
```

Внутри `validate_scene` — обязательные стадии, и порядок не переставляем:
1. **гигиена H0–H4 ДО замыкания** — один ill-typed литерал роняет owlrl и pyshacl (RecursionError),
   а numpy.float64 в xsd:decimal молча отравляет операторы `>` и `<=` в 7 формах;
2. **owlrl.DeductiveClosure(OWLRL_Semantics)** — без него `reflectsFromLayer` (цепочка) и
   `VerticalIonogram` (из сеанса) не выводятся, и формы дают **conforms=True на заведомо неверных
   данных**;
3. pyshacl с содержательными формами, **`advanced=True`**, `inference="none"`.

Вердикт считаем по `sh:Violation`; `sh:Warning` — отдельно (в SHACL любое срабатывание делает
conforms=false, поэтому «допустимо с предупреждениями» надо считать самим — validate.py считает).

## 4. Минимальная сцена (копируйте)

```turtle
@prefix iono: <http://scilibai.ru/onto/iono#> .
@prefix ex:   <http://example.org/scene/> .
@prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .

ex:ion1 a iono:VerticalIonogram ;                 # или Ionogram + producedBy сеанс
    iono:hasObservationTime "2022-01-01T00:00:00Z"^^xsd:dateTime ;
    iono:hasGyroFrequency "1.130"^^xsd:decimal .  # нужна для V4

ex:tr1 a iono:IonogramTrace ; iono:isTraceIn ex:ion1 ; iono:denotes ex:m1 .
ex:m1 a iono:PropagationMode ;
    iono:hasHopCount 1 ; iono:hasRayType iono:lowerRay ;
    iono:hasMagnetoionicComponent iono:ordinary ;
    iono:reflectsFromLayer iono:Layer_F2 ;
    iono:hasMOFValue "8.200"^^xsd:decimal ;
    iono:hasMinDelayValue "1.4877"^^xsd:decimal .  # τ[мс] = 2·h′[км]/299.792

ex:c1 a iono:CriticalFrequencyDatum ;
    iono:isCharacteristicOf ex:ion1 ;
    iono:refersToLayer iono:Layer_F2 ; iono:refersToComponent iono:ordinary ;
    iono:hasNumericValue "8.200"^^xsd:decimal ; iono:hasUnit "МГц" ;
    iono:hasErrorEstimate "0.15"^^xsd:decimal ;
    iono:hasQualifyingLetter iono:QL_U .          # иначе Q5 (Warning)
```

Чек-лист обязательных рёбер (без них объект «сирота» и не проверяется — ловит гигиена):
след → `isTraceIn`; мода ← `denotes`; характеристика → `isCharacteristicOf`; у моды —
`hasHopCount` (integer!) + слой; у характеристики — слой + значение (или причина/буква).

## 6. Правила расширения словаря

1. **Новая мода** — не новый код, а `owl:equivalentClass` из признаков (образец — `Mode_2F2p`
   в ядре). При нестандартном признаке — сначала добавить значение признака.
2. **Новая характеристика** — вид величины × слой × компонента (образец — `Char_fxF2` в char).
3. **Новое ограничение** — новый SHACL-файл или форма (образец задуман `iono-shapes-ext.ttl`).
   Помните про BIND-санацию в сравнениях с `>` / `<=`.
4. **Новое значение словаря** (тип Es, буква, слой) — добавить индивид + внести в
   соответствующий `owl:AllDifferent` и в `sh:in` формы H4.
5. Каждой сущности — `rdfs:label@ru` и `rdfs:comment` со ссылкой на источник
   («РД …, §…, с. N печ.»; печатная страница = PDF − 10). Число не из источника помечать
   («рабочее значение прототипа, подлежит калибровке»).

## 7. Известные ловушки

1. **numpy.float64 → rdflib.Literal(xsd:decimal)** — датитип будет верным, а операторы `>` и
   `<=` в SPARQL молча вернут истину всегда. Стройте литералы ТОЛЬКО через `validate.dec()`.
   Формы дополнительно защищены `BIND(xsd:decimal(STR(…)))`, гигиена H0 ловит на входе.
2. **Забытый owlrl** = «зелёный» отчёт на любых данных. Используйте `validate_scene()`.
3. **`a Mode_1F2` без признаков** — мода невидима для проверок (H5 предупредит).
4. **hasHopCount не integer** — `owl:hasValue 1` не сработает, классификация мод молчит (H0).
5. **`sh:severity` работает только на уровне формы**, не внутри `sh:SPARQLConstraint`.
6. **`sh:class` ходит по rdfs:subClassOf, не по equivalentClass** — определяемым классам,
   участвующим в формах, нужен и явный subClassOf (так сделано для VerticalIonogram).
7. **conforms** у pyshacl ложно при любых результатах, включая Warning — считайте severity сами.
8. **ВЗ- и НЗ-формы теперь композируются** (V-формы таргетируют только VerticalIonogram), но
   Q1 применима только к ВЗ: для наклонного падения порядок наблюдаемых частот не выполняется
   (РД §6.5.6.2: МПЧ 1E 11,5 > МПЧ 1F2 9 МГц).
9. `sh:declare` привязан к узлу `iono:` — pyshacl это ест; для TopBraid/Jena может понадобиться
   перенос деклараций на IRI онтологий форм.

## 8. Регрессионные контроли

`ground-A.ttl` (НЗ, допустимая разметка — из примера РД §7.3.3/§7.3.5, Ловозеро–Горьковская) →
допустима; `ground-B.ttl` (1F2↔2F2 переставлены — визуально та же ионограмма) → S1+S2+S6;
`ground-C.ttl` (верхний луч без нижнего) → S3, C2-вариант с `shortLowerRayAssumption true` →
допустима. Полный набор из 18 сценариев — `python -m pyon.validate` (перечень в самом файле).

## 9. Источники и статус

- **РД 52.26.817–2023** (Росгидромет) — нормативная основа ВЗ-части; постраничная сверка
  выполнена (ревью 04): перечни букв, пороги точности, условие G, коды ИОНКА, типы Es —
  дословно; страницы в аннотациях — печатные (= PDF − 10).
- **URSI Handbook UAG-23A** (Piggott & Rawer, 1978; NOAA public domain) — типы Es d/k/n,
  правила табуляции, запреты (Es-s не для foEs!).
- **Щирый 2007** (диссертация) — словарь мод НЗ, ММЛ, эмпирика S1/S3/S6.
- Помечено как «рабочее значение прототипа»: допуски S2 (×0,95), S4 (0,02 мс), V3 (+0,13/−0,26 мс),
  V4 (±0,3 МГц), Q1 (0,1 МГц), порог частотного spread-F 0,3 МГц. Порог 30 км диапазонного
  рассеяния — НОРМАТИВНЫЙ (РД §6.5.3.4).
- Известное расхождение источников: первый тип Es в табуляции — по foEs (UAG §4.82) или по fbEs
  (РД §6.6.5); проект следует UAG, расхождение зафиксировано в `hasEsType`.
